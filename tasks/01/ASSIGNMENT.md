# 任务 1：业务流程与可信权限

分支：`task-1-workflows-permissions`。预计 **14 小时**，个人预留 12–16 小时；机器排队和后台运行另计。

## 从哪里开始

先阅读日程写入 2/3 与跨服务缺失地点的失败分析；使用当前六个开发任务建立可复现失败记录，再审查 task_inventory.json 中 20 个候选正式任务。

## 工时安排

- 20 个任务与权限审查：4 小时。
- 日程和跨服务稳定性修复：4 小时。
- 权限与 MCP 回归检查：3 小时。
- 方法、失败与局限说明：3 小时。

## 负责文件

experiments/mvp/policies.py、experiments/mvp/mcp_workspace_server.py、experiments/mvp/simulation_runtime.py、configs/study/tasks.json、tests/test_task1_*。自己的 `tasks/01/` 可自由补充。共同接口见 [接口说明](../../docs/INTERFACES_ZH.md)。

## 交付物

20 个测试任务的可信权限来源和字段约束；统一的正常任务稳定性修复；允许合法写入和拒绝越权的测试；开发结果及残余失败说明。

## 验收清单

- [ ] 权限只从原用户请求和攻击前可信目录产生，不读取 ground_truth 或攻击目标。
- [ ] 保持 make_policy 和 authorize 接口；任何新权限默认拒绝未授权工具、对象和收件人。
- [ ] 新权限同时有合法调用和越权调用的测试。
- [ ] 正常业务复测保留每次失败，不能要求模型不停重跑直到 3/3。
- [ ] 与任务 4 对齐正式 task ID 和字段，不自行运行未冻结的正式测试。
- [ ] 所有代码与测试在计算节点执行，记录真实结果和剩余局限。
- [ ] PR 写明影响的接口、验证命令和实际人工工时；完成后由组员审核合并。

## 合作方式

所有人从共同 main 基础开发。正式接口由任务 4 集成；任务 5 可先用历史数据工作。初始化提交仅提供任务材料，不代表此任务已完成。
