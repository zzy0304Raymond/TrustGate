# 任务 2：攻击案例与两个注入入口

分支：`task-2-attack-cases`。预计 **14 小时**，个人预留 12–16 小时；机器排队和后台运行另计。

## 从哪里开始

从 seed_attacks.json 开始复现现有输出攻击，理解为什么现有工具说明攻击在无防护下 0/3；先改开发攻击，再冻结测试模板。

## 工时安排

- 攻击目标和模板族设计：4 小时。
- 案例注入与到达性实现：4 小时。
- 无防护和阴性对照验证：3 小时。
- 案例审查与说明：3 小时。

## 负责文件

configs/attacks/、experiments/attacks/、tests/test_task2_*。自己的 `tasks/02/` 可自由补充。共同接口见 [接口说明](../../../docs/INTERFACES_ZH.md)。

## 交付物

60 个正式案例（输出 30、说明 30）；开发/测试模板家族划分；任务、攻击目标、位置、payload、到达判断和未触发原因；无防护与阴性对照记录。

## 验收清单

- [ ] 60 指全测试集总数，不能误做成每任务 60。
- [ ] 每个案例均记录 split 和 template_family，测试冻结后不根据效果挑选。
- [ ] 工具说明攻击只改变指定描述，不偷偷改工具实现或参数 schema。
- [ ] 工具输出攻击记录注入内容是否实际到达模型。
- [ ] 未攻破无防护时报告攻击未有效，不能声称防护成功。
- [ ] 所有代码与测试在计算节点执行，记录真实结果和剩余局限。
- [ ] PR 写明影响的接口、验证命令和实际人工工时；完成后由组员审核合并。

## 合作方式

所有人从共同 main 基础开发。正式接口由任务 4 集成；任务 5 可先用历史数据工作。初始化提交仅提供任务材料，不代表此任务已完成。
